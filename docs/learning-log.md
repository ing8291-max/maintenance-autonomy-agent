# Learning Log

프로젝트를 돌리며 배운 것과 틀린 것을 날짜별로 적는다. 리포트의 "실패 모드"·"한계" 섹션 재료.

## 2026-10-31

### 배운 것
- Microsoft 는 Azure PdM 샘플 데이터의 **생성 규칙을 공개한 적이 없다**. 시뮬레이션이라는 설명만 있다. 그래서 하드케이스는 역추적도, 처음부터 생성도 아니고, **실제 구간에 섭동을 주입**하는 방식으로 간다 (ADR 0003).
- PHMForge (arXiv 2604.01532) 는 PHM 알고리즘 사용 능력을 재고, 우리는 자율성·안전 축을 잰다. 축을 분리해 포지셔닝하기로 (ADR 0002).
- Failure-as-a-Process (arXiv 2607.09510) 는 CLI 코딩 에이전트 **경험 연구**이지 스코어링 벤치마크가 아니다. 3-시점 라벨링은 영감만 받고 우리가 정비 도메인용으로 설계 (ADR 0006).
- 적시 구간은 `처음 드러남` 이 아니라 `이상 시작` 부터 세야 예지정비의 가치를 잰다 (ADR 0006).
- MLX 는 맥 전용이라 GitHub Actions 리눅스 러너에서 못 돈다. CI 스모크는 가짜 모델로 (ADR 0008).

### 틀린 것
- "Muse Spark 는 Meta 모델이 아닐 것"이라는 초기 사실확인이 틀렸다. 실제로 Meta Global AI Developer Hackathon 의 Meta Model API 라인업에 Muse Spark series 가 있다.
- "비용 가중치 100:10:1 은 정비 문헌의 통상 비율"이라는 표현을 썼다가 교정받았다. **문헌값이 아니라 가정**이다. ADR 0005 와 config 에 그대로 적는다.
- "N억 건 Hypothesis 퍼즈"는 비현실적. 규칙당 2K, 전체 10K 로 정했다 (sharpen 지적).
