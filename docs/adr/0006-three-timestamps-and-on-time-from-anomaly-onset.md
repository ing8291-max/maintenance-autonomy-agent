# 고장은 세 시점으로 라벨링하고, 적시 구간은 `이상 시작` 부터 센다

모든 act 짝 시나리오는 세 시점을 ground truth 로 가진다: `이상 시작` → `처음 드러남` → `되돌릴 수 없는 시점`. 영감은 Failure-as-a-Process(arXiv 2607.09510) 지만, 그 논문은 CLI 코딩 에이전트의 **경험적 실패 궤적 분석**이지 스코어링 벤치마크가 아니다. 세 시점을 ground truth 로 쓰고 그걸로 스코어링하는 설계는 **이 저장소가 정비 도메인용으로 설계**했다.

에이전트의 액션 타임스탬프 `t_act` 를 다음으로 분류한다:
- `t_act < 이상 시작` → **너무 이름** (과잉 에스컬레이션 비용)
- `이상 시작 ≤ t_act ≤ 되돌릴 수 없는 시점` → **적시** (정답)
- `t_act > 되돌릴 수 없는 시점` → **너무 늦음** (놓친 고장 비용)

`적시` 구간을 `처음 드러남` 이 아니라 **`이상 시작` 부터 세는 이유**: 예지정비의 가치는 "에러 코드가 뜨기 전에 알아채는 것"이다. 임계값 모니터링도 할 수 있는 걸 LLM 에이전트가 재현해 봐야 의미 없다.

## Considered Options

- **적시 구간을 `처음 드러남` 부터 세기**: 평가가 "에러 코드 보고 반응"이 되어, 예지정비의 핵심을 못 잰다. 기각.
- **이진 라벨 (조치 vs 유보)**: 언제 조치했는지가 안 보인다. 기각.
- **단일 "고장 시점" 하나**: Failure-as-a-Process 의 통찰(이상은 과정이지 사건이 아니다)을 잃는다. 기각.

## Consequences

- 합성기는 세 시점을 명시적 파라미터로 받고, 각 시나리오 YAML 에 세 값을 박는다.
- 리포트에 `적시 비율` 을 보조 지표로 적는다. 비용 지표가 이미 세 구간을 반영하지만, 적시 비율은 "얼마나 일찍 잡았나" 의 가독성 있는 요약이다.
