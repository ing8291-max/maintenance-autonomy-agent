# 산출물의 중심을 에이전트가 아니라 평가 하네스로 잡는다

이 저장소는 "정비 에이전트를 잘 만든다"가 아니라 "정비 에이전트의 **자율성 판단**을 적대적으로 시험하는 하네스를 만든다"가 중심 주장이다. 이유는 두 가지다. 하나, 좋은 에이전트는 많지만 공정한 시험장은 드물다. 둘, 인접 연구 **PHMForge (arXiv 2604.01532)** 가 이미 "LLM 에이전트가 PHM 알고리즘을 쓰는 능력"을 재고 있어서, 같은 축에서 경쟁하면 뒤처진다. 우리는 **자율성·안전** 축으로 좁혀, PHMForge 가 안 다루는 "언제 혼자 하고, 언제 사람을 부르고, 언제 유보할지"를 잰다.

## Considered Options

- **에이전트 중심**: 모델·프롬프트·툴 체인을 다듬어 수치를 높이는 쪽. 재미있지만 PHMForge 와 축이 같아지고, 솔로가 1주일에 이기기 어렵다. 기각.
- **PHMForge 를 그대로 쓰고 그 위에 자율성 레이어만 얹기**: MCP 툴 체계가 커서 M3 8GB에 안 맞고, 완전 합성 평가를 못 짠다. 기각.

## Consequences

- 리포트의 메인 주장은 "A1(게이트 없음) → A2(게이트 있음) 비교가 자율성·안전 축에서 유의미한 차이를 만든다"이다. 에이전트 성능 상승이 아니라 **정책 게이트의 효과**가 1차 결과다.
- PHMForge 와의 겹침·차이는 리포트 1문단과 ADR 0002에 명시하고, 하네스는 PHMForge "자율성·안전 사이드카"로 포지셔닝한다.
