# 머신 100대를 층화 랜덤으로 70/30 나누고, 평가용 하드케이스 생성 전에 합성기를 잠근다

누수와 사후 튜닝을 막는 두 겹의 장치.

**분할**: 머신 100대를 `machineID` 번호 순으로 자르지 않고, **모델(model) 별 층화 + 시드 고정 무작위**로 70/30 나눈다. 분할 결과는 `data/splits.json` 에 커밋한다. 결정론 재현이 가능해야 한다.
- 개발용 70대: 로지스틱 회귀 학습, 프롬프트·스캐폴딩 튜닝, **개발용 하드케이스 합성**.
- 평가용 30대: easy 자연 시나리오 20건과 **평가용 하드케이스 100건**의 참조 머신 프로파일. 에이전트·베이스라인 튜닝에 절대 노출 금지.

**합성기 잠금**: 평가용 하드케이스를 생성하기 전에 `src/mautonomy/scenarios/synthesizer.py` 를 커밋해 커밋 해시로 잠그고(ADR 또는 README 에 해시 적기), 생성 후에는 **고치지 않는다**. 평가 결과가 마음에 안 들어도 합성기로 돌아가서 "더 공정한" 시나리오로 바꾸면 평가가 깨진다.

## Considered Options

- **번호 순 분할 (1-70 / 71-100)**: 모델 종류 분포가 치우칠 위험. 기각.
- **합성기 자유 수정**: 솔로 1주일엔 유혹이 크지만, "다른 사람이 돌려도 같은 숫자" 가 핵심 주장이라 양보할 수 없다. 기각.

## Consequences

- 합성기 버그를 평가 생성 후에 발견하면 전체 평가를 다시 돌려야 한다. 이 비용을 받아들인다.
- 분할 재현 테스트(`tests/test_splits.py`) 1개 추가.
- 개발용 합성 하드케이스와 평가용 합성 하드케이스는 서로 다른 머신 풀에서 생성됐음을 각 YAML `machine_profile_ref` 로 확인 가능.
