# 하드케이스는 Azure PdM 실제 구간에 섭동을 주입해 만든다

처음 계획은 "Azure PdM 데이터의 생성 규칙(Microsoft 공개 설명)을 거슬러 올라가 요약"하는 것이었다. 그러나 공개 자료(Microsoft Learn, GitHub Azure-Samples, 2016 Cortana Intelligence Gallery 블로그)에는 "시뮬레이션 데이터"라는 설명만 있고, 고장 시딩·사전 드리프트·에러-고장 상관의 **생성 공식은 어디에도 공개되지 않았다**.

그래서 역추적도 하지 않고, 생성 모델을 처음부터 만들지도 않는다. 대신 **실제 Azure PdM 의 구간을 바탕으로 그 위에 함정(섭동)을 주입**한다. 각 하드케이스는:

1. 평가용 머신 30대 중 하나에서 **실제 텔레메트리·에러·정비 기록 구간**을 뽑고,
2. 그 구간에 패밀리별 섭동(F1 신호 중첩, F2 센서 결측, F3 최근 교체 잔존, F4 에러코드 거짓 양성, F5 프롬프트 인젝션)을 코드로 주입하고,
3. 섭동 결과로 생기는 3-시점 ground truth 를 라벨링한다.

주입 방법·베이스 구간 선택 기준·3-시점 산정 규칙은 전부 `docs/synthesis-protocol.md` 에 적는다. 실제 Azure PdM CSV 는 easy 자연 분포 시나리오 20건의 소스이기도 하다.

## Considered Options

- **데이터에서 통계적으로 역추적**: 가능하지만 신뢰할 수 없고, 리포트에서 "우리가 추정한 규칙"으로 밖에 못 쓴다. 기각.
- **생성 모델을 처음부터 설계**: 신호가 "진짜 같지" 않다. 리뷰어가 "장난감"이라고 평가할 위험. 기각.
- **실제 데이터만 사용 (섭동 없음)**: 하드케이스를 자연 분포에서 찾기 어렵고, 3-시점 ground truth 를 알 수 없다. 기각.

## Consequences

- 섭동 코드는 명시적이고 결정론적이어야 한다. 각 시나리오 YAML 에 "어느 머신·어느 구간·어떤 섭동"을 적어 재생성 가능하도록.
- 베이스 구간은 Azure 데이터이므로 시나리오 YAML 전체는 `data/synth/` (gitignore). ADR 0008 참조.
- Azure PdM 데이터의 생성 규칙이 미공개라는 사실 자체를 리포트의 "데이터와 시나리오" 섹션에 명시한다.
