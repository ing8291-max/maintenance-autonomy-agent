# 하드케이스는 Microsoft 규칙을 역추적하지 않고 우리가 직접 만든다

처음 계획은 "Azure PdM 데이터의 생성 규칙(Microsoft 공개 설명)을 거슬러 올라가 요약"하는 것이었다. 그러나 공개 자료(Microsoft Learn, GitHub Azure-Samples, 2016 Cortana Intelligence Gallery 블로그)에는 "시뮬레이션 데이터"라는 설명만 있고, 고장 시딩·사전 드리프트·에러-고장 상관의 **생성 공식은 어디에도 공개되지 않았다**. 그래서 역추적 대신 **우리가 생성 규칙을 설계·문서화해서 하드케이스를 합성**한다. 실제 Azure PdM CSV는 (1) 스키마와 신호 모양을 맞추는 참조 표면, (2) easy 자연 분포 시나리오 20건의 소스로만 쓴다.

## Considered Options

- **데이터에서 통계적으로 역추적**: 가능하지만 신뢰할 수 없고, 리포트에서 "우리가 추정한 규칙"으로 밖에 못 쓴다. 투명성이 떨어진다. 기각.
- **실제 데이터만 사용**: 하드케이스를 자연 분포에서 찾기 어렵고, 3-시점 ground truth 를 알 수 없다. 기각.

## Consequences

- 생성 규칙 전부를 `docs/synthesis-protocol.md` 에 적는다. 하드케이스 패밀리 5종(F1-F5)별로 어떤 신호를 어떻게 삽입하는지 명시한다.
- 하네스의 투명성 측면에서 오히려 유리하다: 모든 ground truth 가 우리 코드에서 나오므로 검증 가능하다.
- Azure PdM 데이터의 생성 규칙이 미공개라는 사실 자체를 리포트의 "데이터와 시나리오" 섹션에 명시한다.
